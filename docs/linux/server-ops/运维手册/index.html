Linux系统运维权威手册

第一部分：基础入门​

第一章：运维与操作系统核心概念​

1.1 运维工程师的角色与技能​

运维工程师（Operations Engineer）是负责维护并确保整个服务的高可用性、稳定性和安全性的专业技术人员。他们不仅要处理日常的服务器管理、故障排查，还要不断优化系统架构，提升部署效率与系统可靠性。

1.2 操作系统概述与Linux特点​

操作系统（Operating System, OS）是管理计算机硬件与软件资源的程序，是用户与计算机硬件之间的桥梁。

Linux系统特点：

  • 开源：源代码开放，可自由修改和分发。
  • 多用户、多任务：支持多个用户同时登录，并执行多个任务。

1.3 Linux发展简史与主流发行版​

  • 1969年：Unix 系统诞生于贝尔实验室。
  • 1991年：Linus Torvalds 发布了 Linux 内核。
  • 主流发行版：
    • Red Hat / CentOS：企业级应用广泛，稳定性强。
    • Ubuntu / Debian：桌面用户友好，社区活跃。

1.4 操作系统核心组成与工作原理​

原理说明：用户通过Shell（如Bash）输入命令，Shell将这些命令翻译成系统调用（System Call），并传递给操作系统的核心——内核（Kernel）。内核接收到指令后，驱动相应的硬件（CPU、内存、磁盘等）来完成操作，并将结果返回给Shell，最终显示给用户。

+-------------------+
|    应用程序       |  <-- 用户交互层
+-------------------+
        | (发出指令)
        v
+-------------------+
|   Shell (解释器)  |  <-- 将命令翻译成系统调用
+-------------------+
        | (发起系统调用)
        v
+-------------------+
|    内核 (Kernel)  |  <-- 接收调用，管理硬件
+-------------------+
        | (驱动硬件)
        v
+-------------------+
|      硬件层       |  <-- 物理设备执行操作
+-------------------+

第二章：服务器硬件与系统安装​

2.1 服务器硬件核心组件​

  • CPU：中央处理器，核心指标为路数（物理CPU颗数）和核心数。
  • 内存(Memory)：临时数据存储区。
  • 硬盘(Disk)：永久数据存储。
  • RAID卡：磁盘阵列卡，用于提升磁盘性能或提供数据冗余。

2.2 磁盘阵列(RAID)原理详解​

RAID (独立磁盘冗余阵列) 技术通过数据分发和/或备份，在多块磁盘上实现性能提升和数据冗余。

  • RAID 0 (条带化): 将数据分成块，并行写入多块磁盘。读写速度最快，但无冗余，任何一块磁盘损坏都会导致所有数据丢失。
  • RAID 1 (镜像): 将数据完全复制到另一块磁盘。数据安全性最高，但磁盘利用率只有50%。
  • RAID 5 (带奇偶校验的条带化): 将数据和对应的奇偶校验信息存储到不同的磁盘上。兼顾了性能、成本和安全性，允许一块磁盘损坏。
  • RAID 10 (镜像+条带化): 先做RAID 1（镜像），再对镜像组做RAID 0（条带化）。性能和安全性都非常高，但成本也是最高的。

2.3 操作系统安装部署​

关键步骤：

  1. 配置虚拟网络：实验环境通常使用VMware的NAT模式。
  2. 加载系统镜像：选择合适的ISO镜像文件。
  3. 磁盘分区：
    • /boot：存放引导文件 (200-500MB)。
    • swap：交换分区 (物理内存的1-2倍)。
    • /：根分区。
  4. 网络配置：设置静态IP、网关、DNS。

第二部分：系统管理​

第三章：基础命令与文件操作​

3.1 远程连接与基础命令​

  • 远程连接：使用Xshell等工具通过SSH协议连接。
  • 基础命令：ls, cd, mkdir, touch, rm, cp, mv。

3.2 系统目录结构详解​

  • /etc：系统配置文件。
  • /var：经常变化的文件，如日志 (/var/log)。
  • /proc：虚拟文件系统，内核与进程信息。
  • /home：普通用户的家目录。
  • /root：root用户的家目录。

3.3 vim 编辑器高级技巧​

  • 三种模式: 命令模式、编辑模式、底行模式。
  • 常用操作:
    • i / a / o: 进入编辑模式。
    • dd: 删除行。
    • yy: 复制行。
    • p: 粘贴。
    • :wq: 保存并退出。
    • :q!: 不保存强制退出。

3.4 文本处理三剑客：grep, sed, awk​

  • grep: 文本搜索工具，用于查找包含指定模式的行。
  • sed: 流编辑器，用于对文本进行行级别的替换、删除、插入。
  • awk: 强大的文本分析工具，擅长按列处理文本。

第四章：用户与权限管理​

4.1 用户与用户组核心概念​

  • 用户分类: 管理员(root)、普通用户、虚拟用户。
  • 核心文件:
    • /etc/passwd: 用户账户信息。
    • /etc/shadow: 用户密码信息。
    • /etc/group: 用户组信息。

4.2 用户管理实战​

  • 用户命令: useradd, passwd, usermod, userdel。
  • 用户组命令: groupadd, groupmod, groupdel。
  • 查看用户信息: id, whoami, w, last。

4.3 文件权限深度解析​

  • 基本权限 (rwx): 读(4)、写(2)、执行(1)。
  • chmod: 修改文件权限。
  • chown: 修改文件所有者和所属组。
  • 特殊权限:
    • SUID (s): 执行时临时获得文件所有者的权限。
    • SGID (s): 新建文件/目录继承父目录的所属组。
    • 粘滞位 (t): 目录下文件只有所有者和root可删除。

4.4 文件链接原理：软链接与硬链接​

原理说明：Linux文件系统通过inode（索引节点）来标识文件。inode存储文件的元数据（权限、所有者、大小等）和指向数据块的指针，而文件名则存储在目录的数据块中，仅仅是指向inode的一个标签。

  • 硬链接 (Hard Link): ln source link，创建了一个新的文件名，指向与源文件相同的inode。因此，删除源文件不影响硬链接，只有当所有指向该inode的链接都被删除后，数据才会被真正删除。它不能跨文件系统，也不能对目录创建。
  • 软链接 (Symbolic Link): ln -s source link，创建了一个新的inode和新的文件，这个文件的内容是源文件的路径。它类似Windows的快捷方式，如果源文件被删除，软链接就会失效。它可以跨文件系统。

第三部分：进阶运维​

第五章：系统监控与性能优化​

5.1 /proc 虚拟文件系统​

  • /proc/cpuinfo: CPU信息。
  • /proc/meminfo: 内存信息。
  • /proc/loadavg: 系统负载。

5.2 基础系统优化策略​

  1. 关闭不必要的服务：如 firewalld, SELinux。

  2. 优化YUM源：更换为国内镜像源。

  3. 时间同步：timedatectl set-ntp true。

  4. 自定义命令提示符(PS1):

    # 编辑 ~/.bashrc 文件
    RED='\[\033[01;31m\]'
    GREEN='\[\033[01;32m\]'
    YELLOW='\[\033[01;33m\]'
    END='\[\033[0m\]'
    PS1="[$RED\u$END@$YELLOW\h$END $GREEN\W$END]\\$ "

第六章：系统服务与自动化任务​

6.1 Linux系统启动流程原理 (CentOS 6 vs 7)​

  • CentOS 6 (init): 采用init进程（PID=1），依赖 /etc/inittab 文件和 rc 脚本，服务按顺序串行启动，启动速度较慢。
  • CentOS 7 (systemd): 采用systemd进程（PID=1），使用 target 单元文件管理服务依赖，可以并行启动多个服务，启动速度显著提升。

6.2 计划任务 (Crontab) 详解与原理​

原理说明：crond是一个常驻后台的守护进程，它会每分钟检查一次 /var/spool/cron/ 目录下各用户的任务文件以及 /etc/crontab 系统任务文件，判断是否有任务需要在此刻执行。

  • crontab -e: 编辑当前用户的定时任务。
  • crontab -l: 查看任务。

格式:

# 分  时  日  月  周  要执行的命令
# * * * * * command

常见错误：

  • 命令路径问题：cron的环境变量非常有限，建议所有命令都使用绝对路径。
  • 特殊符号转义：% 在cron中有换行的特殊含义，需要转义为 \%。
  • 输出重定向：将输出重定向到 /dev/null 2>&1 避免产生垃圾邮件。

第七章：SSH服务深度应用​

7.1 SSH原理与文件传输​

原理说明：SSH (Secure Shell) 通过非对称加密（公钥/私钥）和对称加密相结合的方式工作。

  1. 握手阶段：客户端和服务器使用非对称加密协商出一个临时的对称加密密钥。
  2. 会话阶段：之后的所有通信都使用这个临时的对称密钥进行加密，速度快且安全。
  • 客户端工具: ssh (远程登录), scp (远程拷贝)。

7.2 SSH密钥认证配置实战​

原理说明：用户将自己的公钥存放在远程服务器上。登录时，服务器用这个公钥加密一段随机数据发送给客户端，客户端用自己的私钥解密后发回给服务器。服务器验证成功后，即允许登录，全程无需传输密码。

实验环境：

  • 客户端A: 192.168.1.10
  • 服务器B: 192.168.1.20

操作步骤：

  1. 在客户端A生成密钥对:

    # ssh-keygen -t rsa
    # 一路回车，会在 ~/.ssh/ 目录下生成 id_rsa (私钥) 和 id_rsa.pub (公钥)

  2. 将客户端A的公钥拷贝到服务器B:

    # ssh-copy-id -i ~/.ssh/id_rsa.pub root@192.168.1.20
    # 需要输入一次服务器B的root密码

  3. 测试免密登录:

    # ssh root@192.168.1.20

7.3 SSH安全优化策略​

编辑 /etc/ssh/sshd_config 文件，进行以下安全加固：

  • 禁止root用户直接登录: PermitRootLogin no
  • 更改默认端口: Port 6666
  • 仅使用密钥认证: PasswordAuthentication no
  • 加快连接速度:
    • UseDNS no (禁止反向DNS解析)
    • GSSAPIAuthentication no (禁止GSS认证)

第四部分：高级存储与数据同步​

第八章：磁盘与存储管理​

8.1 磁盘物理与逻辑结构​

  • 物理结构: 盘片、磁头、主轴。
  • 逻辑结构: 磁道、扇区、块。

8.2 磁盘分区、格式化与挂载​

  1. 分区: fdisk (小于2TB) 或 parted (大于2TB)。
  2. 格式化: mkfs.xfs /dev/sdb1 (创建文件系统)。
  3. 挂载: mount /dev/sdb1 /data。
  4. 自动挂载: 编辑 /etc/fstab 文件。

8.3 LVM逻辑卷管理原理与实战​

原理说明：LVM在物理磁盘和文件系统之间增加了一个逻辑层。它将多个物理分区（PV）聚合成一个大的存储池（VG），然后按需从这个池中划分出逻辑分区（LV）。由于LV的大小不再受限于单个物理磁盘的大小，因此可以非常方便地进行动态扩容和缩容。

核心概念:

  • PV (Physical Volume): 物理卷。
  • VG (Volume Group): 卷组，存储池。
  • LV (Logical Volume): 逻辑卷，从VG中划分。
  • PE (Physical Extent): 物理扩展单元，VG中最小存储块。

实验环境：

  • 新增磁盘: /dev/sdb (20G)

操作流程:

  1. fdisk /dev/sdb: 创建一个新分区 /dev/sdb1。
  2. pvcreate /dev/sdb1: 将分区初始化为物理卷。
  3. vgcreate vg_data /dev/sdb1: 创建名为 vg_data 的卷组。
  4. lvcreate -n lv_data -L 10G vg_data: 从 vg_data 中创建10G的逻辑卷 lv_data。
  5. mkfs.xfs /dev/vg_data/lv_data: 格式化逻辑卷。
  6. mkdir /data; mount /dev/vg_data/lv_data /data: 挂载使用。

LVM在线扩容实战:

  1. lvextend -L +5G /dev/vg_data/lv_data: 将LV扩展5G。
  2. xfs_growfs /data: 将文件系统大小同步到LV大小。

第九章：数据备份与网络存储​

9.1 备份策略与工具概述​

  • 全量备份: 备份所有数据。
  • 增量备份: 只备份自上次备份以来发生变化的数据。

9.2 Rsync远程同步实战案例​

场景: 将NFS服务器 /data 目录的数据，通过Rsync守护进程模式，定时备份到Backup服务器的 /backup 目录。

实验环境:

  • NFS服务器 (Client): 172.16.1.31
  • Backup服务器 (Server): 172.16.1.41

1. Backup服务器端配置 (rsync-server)

  • 安装: yum install -y rsync

  • 创建配置文件: vim /etc/rsyncd.conf

    uid = rsync
    gid = rsync
    port = 873
    fake super = yes
    use chroot = no
    max connections = 200
    timeout = 600
    pid file = /var/run/rsyncd.pid
    lock file = /var/run/rsync.lock
    log file = /var/log/rsyncd.log

    [backup]
    path = /backup
    comment = backup dir
    read only = false
    hosts allow = 172.16.1.0/24
    auth users = rsync_backup
    secrets file = /etc/rsync.password

  • 创建用户和密码文件:

    useradd rsync -s /sbin/nologin -M
    echo "rsync_backup:123456" > /etc/rsync.password
    chmod 600 /etc/rsync.password

  • 创建备份目录并授权: mkdir /backup; chown -R rsync.rsync /backup

  • 启动服务: systemctl start rsyncd

2. NFS客户端配置 (rsync-client)

  • 安装: yum install -y rsync

  • 创建密码文件: echo "123456" > /etc/rsync.password; chmod 600 /etc/rsync.password

  • 执行推送命令:

    rsync -avz /data/ rsync_backup@172.16.1.41::backup --password-file=/etc/rsync.password

9.3 NFS 网络文件系统配置​

NFS (Network File System) 允许网络中的计算机之间共享目录和文件。

服务器端配置:

  1. 安装: yum install -y nfs-utils

  2. 配置 /etc/exports:

    /data   192.168.1.0/24(rw,sync)

  3. 启动服务: systemctl start nfs-server rpcbind

客户端配置:

  1. 安装: yum install -y nfs-utils
  2. 挂载: mount -t nfs [服务器IP]:/data /mnt

第十章：Web服务基础​

10.1 HTTP协议基础​

HTTP (超文本传输协议) 是Web数据交换的基础。

  • 常见请求方法: GET (获取资源), POST (提交数据)。
  • 常见响应状态码: 200, 301, 403, 404, 500, 502, 504。

10.2 LNMP架构原理与PHP安装​

LNMP 指的是 Linux + Nginx + MySQL + PHP。

  • 工作流程: Nginx处理静态请求，并将动态请求通过FastCGI转发给PHP-FPM处理。
  • PHP安装:
    1. 安装EPEL源。
    2. 添加PHP的YUM源。
    3. yum install php71w php71w-fpm php71w-mysqlnd ...

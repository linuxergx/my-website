# 运维网络与防火墙核心知识点 (图解版)




### 第一部分：网络基础理论 (入门)

## 1. 网络通信基础

#### 通信三要素

1. **传输介质**: 网线、光纤、WiFi 等。
2. **网卡设备**: 数据的发送和接收硬件。
3. **通信协议**: 双方必须遵守的规则。

#### 核心网络设备

- **交换机 (Switch)**: 在**同一个局域网**内，根据 **MAC 地址**转发数据。
- **路由器 (Router)**: 连接**不同的网络**，根据 **IP 地址**转发数据。

```
      局域网 A (192.168.1.0/24)                    局域网 B (10.0.0.0/24)
+-----------------------------------+         +-----------------------------------+
|   PC1 ---+                        |         |                        +--- PC3   |
|          |                        |         |                        |          |
|          [交换机 A] --               [路由器] --             [交换机 B] |
|          |                        |         |                        |          |
|   PC2 ---+                        |         |                        +--- PC4   |
+-----------------------------------+         +-----------------------------------+
```

## 2. 网络模型

### OSI 七层模型

一个理论上的网络通信标准框架。

### 数据封装与解封装

数据在发送时，从上到下逐层“打包”（封装）；在接收时，从下到上逐层“拆包”（解封装）。

```bas
     发送端                                                接收端
+---------------+                                     +---------------+
|   应用层      | -- 数据 -->                           |   应用层       |
+---------------+                                     +---------------+
|   传输层      | -- [TCP头|数据] --> (段)              |   传输层       |
+---------------+                                     +---------------+
|   网络层      | -- [IP头|段] --> (包)                 |   网络层       |
+---------------+                                     +---------------+
| 数据链路层    | -- [MAC头|包|尾] --> (帧)              | 数据链路层      |
+---------------+                                     +---------------+
|   物理层      | -- 10101101 (比特流) -->              |   物理层       |
+---------------+                                     +---------------+
```

### TCP/IP 模型

实际应用最广泛的模型，通常分为四层。

## 3. 核心网络协议

### ARP 协议 (地址解析)

**作用**: IP 地址 -> MAC 地址。

```
+-------+                                           +-------+
|  PC A |                                           |  PC B |
| IP: .1|                                           | IP: .2|
| MAC: ?|                                           | MAC: BB|
+-------+                                           +-------+
    |                                                   ^
    | --- ARP 请求 (广播): "谁是 192.168.1.2?" --->       |
    |                                                   |
    | <--- ARP 响应 (单播): "我是, 我的 MAC 是 BB" ---     |
    |                                                   |
    v
  更新 ARP 缓存: 192.168.1.2 -> BB
```

### DNS 协议 (域名解析)

**作用**: 域名 -> IP 地址。

### DHCP 协议 (动态地址分配)

**作用**: 自动分配 IP 地址等网络配置。

### 第二部分：IP 地址详解 (进阶)

## 4. IP 地址基础

### IP 地址的组成

32位二进制数，分为**网络部分 (Network ID)** 和 **主机部分 (Host ID)**。

### IP 地址的分类 (A/B/C/D/E)

| 类别 | 第一字节范围 | 默认子网掩码          |
| ---- | ------------ | --------------------- |
| A 类 | 1 - 126      | `255.0.0.0` (/8)      |
| B 类 | 128 - 191    | `255.255.0.0` (/16)   |
| C 类 | 192 - 223    | `255.255.255.0` (/24) |

### 公网与私网地址

- **公网地址**: 全球唯一，用于互联网。
- **私网地址**: 可在局域网内重复使用 (`10.x.x.x`, `172.16-31.x.x`, `192.168.x.x`)。

### NAT 技术 (网络地址转换)

**作用**: 让多个私网地址共享一个公网地址上网。

```properties
+---------------------------------+      +-----------------+      +-----------+
| 局域网                           |      |                 |      |           |
| PC (192.168.1.10) -- 数据包 -->  | ---> | NAT设备(路由器)   | ---> |  互联网    |
| SrcIP: 192.168.1.10             |      |                 |      |           |
+---------------------------------+      +-----------------+      +-----------+
                                           |
                                           v
                                     转换源IP为公网IP
                                     SrcIP: 202.100.1.1
```

## 5. 子网划分 (VLSM)

### 子网掩码的作用

用来区分 IP 地址的网络位和主机位。

### 为何要划分子网

1. 节约 IP 地址。
2. 减少广播流量，提高性能。
3. 简化管理。

### 子网划分计算方法

**核心**: 从主机位借位给网络位。

- **子网数量**: `2^n` (n = 借的位数)
- **每个子网的主机数**: `2^m - 2` (m = 剩余的主机位数)
  - **修正**: `-2` 是因为每个子网的第一个地址（全0）是网络地址，最后一个地址（全1）是广播地址，这两个不能分配给主机。

### 第三部分：传输层与路由 (深入)

## 6. 传输层协议 TCP 与 UDP

### TCP vs UDP

| 特性         | TCP (可靠)         | UDP (高效)       |
| ------------ | ------------------ | ---------------- |
| **连接**     | 面向连接           | 无连接           |
| **可靠性**   | 可靠，有确认、重传 | 不可靠，尽力而为 |
| **应用场景** | Web, Email, FTP    | DNS, 视频, 语音  |

### TCP 三次握手 (连接建立)

```
   客户端                                  服务器
     |                                      |
     | ------------ SYN=1, seq=x ---------> |
     |                                      |
     | <---- SYN=1, ACK=1, seq=y, ack=x+1 --|
     |                                      |
     | ------------ ACK=1, ack=y+1 -------->|
     |                                      |
     +--------------------------------------+
             连接建立 (ESTABLISHED)
```

### TCP 四次挥手 (连接断开)

```
   主动方                                 被动方
     |                                      |
     | ------------ FIN=1, seq=u ---------> |
     |                                      |
     | <------------ ACK=1, ack=u+1 ------- |
     |                                      |
     |         (等待数据发送完毕）             |
     |                                      |
     | <------------ FIN=1, seq=w --------- |
     |                                      |
     | ------------ ACK=1, ack=w+1 -------> |
     |                                      |
     +--------------------------------------+
             连接关闭 (CLOSED)
```

### TCP 状态集

`netstat -antp` 可以查看 `LISTEN`, `ESTABLISHED`, `TIME_WAIT` 等状态。

## 7. 路由配置

### 静态路由与动态路由

- **静态路由**: 手动配置，适用于简单网络。
- **动态路由**: 路由器间自动学习，适用于复杂网络。

### Linux 系统路由配置

```

```

## 8. 防火墙基础

### 运维安全体系简介

安全是多层面的，网络层防火墙是其中重要一环。

### 防火墙在企业中的应用策略

通常仅在暴露于公网的服务器上开启严格的防火墙策略。

## 9. iptables 防火墙

### iptables 的四表五链

`iptables` 的核心是“表”和“链”。数据包按特定顺序流经这些链，并被表中的规则处理。

```
数据包流向图 (以转发为例):

                                     +-----------------+
                                     |  本机应用程序   |
                                     +-----------------+
                                        ^           |
                                        |           v
---> PREROUTING --> 路由决策 --> FORWARD --> POSTROUTING --->
         |             |             ^
         |             v             |
         +------> INPUT       OUTPUT +------>
```

- **四张表 (功能)**: `filter` (过滤), `nat` (地址转换), `mangle` (标记), `raw` (连接追踪)。
- **五条链 (位置)**: `PREROUTING`, `INPUT`, `FORWARD`, `OUTPUT`, `POSTROUTING`。

### iptables 基础操作

```
# 查看 filter 表规则
iptables -nL
# 清空所有规则
iptables -F
```

### Filter 表规则实践

```
# 允许已建立的连接通过 (非常重要)
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 允许 SSH 端口
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 设置默认拒绝所有入站流量
iptables -P INPUT DROP
```

### NAT 表规则实践 (SNAT)

实现内网主机共享上网。

```
# 开启内核转发
echo 1 > /proc/sys/net/ipv4/ip_forward

# 添加 SNAT 规则
iptables -t nat -A POSTROUTING -s 172.16.1.0/24 -o eth0 -j MASQUERADE
```

## 10. Firewalld 防火墙

`firewalld` 是 CentOS 7+ 默认的防火墙管理工具，基于**区域 (Zone)** 进行管理，比 `iptables` 更动态、更易用。

### 10.1 区域 (Zone) 基础操作

- **查看默认区域**:

  ```
  firewall-cmd --get-default-zone
  ```

- **查看活动区域及绑定的网卡**:

  ```
  firewall-cmd --get-active-zones
  ```

- **查看指定区域的详细规则**:

  ```
  firewall-cmd --list-all
  ```

### 10.2 端口与服务管理

- **添加放行端口** (所有操作建议加上 `--permanent` 使其永久生效，然后 `--reload`):

  ```
  # 放行单个端口
  firewall-cmd --permanent --add-port=8080/tcp
  # 放行多个端口
  firewall-cmd --permanent --add-port={8081,8082}/tcp
  # 放行连续端口
  firewall-cmd --permanent --add-port=8090-8095/tcp
  ```

- **移除端口**:

  ```
  firewall-cmd --permanent --remove-port=8080/tcp
  ```

- **添加放行服务**: 服务是端口的集合，更易于理解。

  ```
  firewall-cmd --permanent --add-service=http
  ```

- **自定义服务**:

  1. 复制一个现有的服务文件作为模板。

     ```
     cp /usr/lib/firewalld/services/http.xml /etc/firewalld/services/nginx.xml
     ```

  2. 编辑新的 xml 文件，修改端口等信息。

  3. 重载防火墙后即可使用新服务。

     ```
     firewall-cmd --reload
     firewall-cmd --permanent --add-service=nginx
     ```

### 10.3 端口转发 (Port Forwarding)

用于将访问本机的某个端口的流量，转发到另一台主机的指定端口上（类似四层负载）。

- **前提**: 必须开启地址伪装 (masquerade)。

  ```
  firewall-cmd --permanent --add-masquerade
  ```

- **添加转发规则**:

  ```
  # 将访问本机 5555 端口的 TCP 流量转发到 172.16.1.7 的 22 端口
  firewall-cmd --permanent --add-forward-port=port=5555:proto=tcp:toport=22:toaddr=172.16.1.7
  ```

### 10.4 富规则 (Rich Rules)

用于实现更精细、更复杂的访问控制策略。

- **查看帮助**: `man firewalld.richlanguage`

- **基本语法**: `rule family="ipv4" source address="IP/CIDR" [service|port|forward-port] [accept|reject|drop]`

- **实践场景**:

  1. **允许特定 IP 访问特定端口**:

     ```
     # 允许 10.0.0.1 访问 80 端口
     firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address="10.0.0.1/32" port port="80" protocol="tcp" accept'
     ```

  2. **拒绝特定网段访问服务**:

     ```
     # 拒绝 172.16.1.0/24 网段通过 ssh 连接
     firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address="172.16.1.0/24" service name="ssh" drop'
     ```

  3. **组合策略**: 允许所有人访问 http/https，但仅允许特定 IP 访问 ssh。

     ```
     # 先移除 ssh 服务的全局允许规则
     firewall-cmd --permanent --remove-service=ssh
     # 添加 http 和 https
     firewall-cmd --permanent --add-service=http
     firewall-cmd --permanent --add-service=https
     # 使用富规则单独允许 10.0.0.1 访问 ssh
     firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address="10.0.0.1/32" service name="ssh" accept'
     ```

  4. **带源地址的端口转发**:

     ```
     # 仅当请求来自 10.0.0.1 时，才将 6666 端口转发到 172.16.1.7 的 22 端口
     firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address="10.0.0.1/32" forward-port port="6666" protocol="tcp" to-port="22" to-addr="172.16.1.7"'
     ```

### 10.5 实现共享上网 (NAT)

1. **在网关服务器上开启地址伪装**:

   ```
   firewall-cmd --permanent --add-masquerade
   ```

2. **在内网客户端上配置网关**:

   - 将客户端的默认网关 (`GATEWAY`) 指向开启了地址伪装的服务器的内网 IP。
   - 配置 DNS (`DNS1`)。
   - 重启网络服务。

3. **测试**: 客户端即可 `ping baidu.com`。

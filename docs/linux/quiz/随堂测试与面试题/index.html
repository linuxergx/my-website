第一章：运维基础入门​

1.1 运维工程师职业素养​

作为一名运维工程师，需要具备以下核心职业素质：

  • 7x24小时响应意识：确保线上服务的持续稳定运行，随时准备应对突发状况。
  • 持续学习能力：技术日新月异，必须保持学习的热情，不断掌握新知识、新技能。
  • 责任心与严谨性：对操作的每一步都心存敬畏，细心谨慎，避免因疏忽导致故障。
  • 良好的沟通与协作能力：运维工作常涉及多部门协作，有效沟通是解决问题的关键。

1.2 服务器硬件基础​

服务器是承载服务的基础，了解其硬件构成至关重要。

  • CPU (中央处理器)：负责运算和控制，是服务器的大脑。
    • 路数：指服务器主板上物理CPU的个数。
    • 核数：指单个物理CPU内部的核心数量。
  • 内存 (Memory)：临时存储数据，速度快但断电后数据会丢失。
    • Buffer (缓冲)：主要用于解决写入磁盘时速度不匹配的问题，将数据先写入内存缓冲区，再批量写入磁盘。
    • Cache (缓存)：主要用于加速读取，将磁盘中频繁读取的数据缓存到内存中。
    • 高并发写入方案：为应对高并发写入请求，通常采用先将数据写入内存，再定时或定量地从内存异步刷写到磁盘的策略，以提高响应速度和系统吞吐量。
  • 磁盘 (Disk)：永久存储数据，速度相对较慢。
    • RAID (独立磁盘冗余阵列)：通过组合多块硬盘，提供更高的数据可靠性或读写性能。
      • RAID 0：条带卷。至少需要1块盘。数据被分成块，交错写入所有磁盘。
        • 优点：读写性能最高。
        • 缺点：无冗余，任何一块硬盘损坏都会导致所有数据丢失。
      • RAID 1：镜像卷。至少需要2块盘。数据在每块磁盘上都有一个完整的副本。
        • 优点：100%冗余，可靠性高。
        • 缺点：磁盘利用率只有50%。
      • RAID 5：带奇偶校验的条带卷。至少需要3块盘。数据和奇偶校验信息交错存储在所有磁盘上。
        • 优点：兼顾了性能、成本和可靠性。
        • 缺点：写入性能相对较差，允许损坏一块硬盘。
  • 网卡 (Network Card)：负责计算机之间的网络通信。
  • 电源 (Power Supply)：为服务器提供电力。

1.3 操作系统核心概念​

  • 操作系统组成：操作系统是管理计算机硬件与软件资源的程序，其核心组成部分包括：
    • 内核 (Kernel)：操作系统的核心，负责管理硬件资源。
    • Shell (命令解释器)：用户与内核交互的接口，例如 bash。
    • 软件/应用程序 (Software)：运行在操作系统之上的各类程序。
  • 自由软件与开源许可
    • GNU (革奴计划)：由自由软件基金会发起，旨在创建一个完全自由的操作系统。
    • GPL (通用公共许可证)：一种广泛使用的自由软件许可证，保障用户自由使用、修改和分发软件的权利。
  • 虚拟机网络模式
    • NAT (网络地址转换)：虚拟机可以访问外部网络，但与宿主机不在同一网段，外部网络无法直接访问虚拟机。
    • 仅主机 (Host-Only)：虚拟机只能与宿主机通信，默认不能访问外部网络。
    • 桥接 (Bridged)：虚拟机与宿主机在同一网段，如同局域网内的一台独立主机，可以直接与外部网络通信。

1.4 Linux 系统安装与分区策略​

合理的磁盘分区是系统稳定和高效运行的基础。 分区方案示例 (300G硬盘, 16G内存)

  1. 标准分区法:
    • /boot: 200MB 或 1GB (存放系统引导文件)
    • swap: 8GB (交换分区，一般为内存的0.5-2倍，内存较大时可适当减小)
    • /: 剩余全部空间 (根分区)
  2. 重要数据分区法:
    • /boot: 200MB 或 1GB
    • swap: 8GB
    • /: 100GB (根分区，存放系统和软件)
    • /data: 剩余全部空间 (独立的数据分区，便于数据管理和备份)
  3. 未知分区法 (LVM):
    • /boot: 200MB 或 1GB
    • swap: 8GB
    • /: 100GB
    • 剩余空间不分配，留作逻辑卷(LVM)以后按需分配。

第二章：Linux 核心命令与操作​

2.1 基础命令入门​

  • 获取帮助
    • man <命令>：查看命令的详细手册页。
    • <命令> --help：查看命令的简要帮助信息。
  • 常用快捷键
    • Ctrl + C：终止当前运行的命令。
    • Ctrl + D：退出当前终端或表示输入结束。
    • Ctrl + L：清屏。
    • Ctrl + A：光标移动到行首。
    • Ctrl + E：光标移动到行尾。
    • Ctrl + U：剪切光标之前的内容。
    • Ctrl + K：剪切光标之后的内容。
    • Ctrl + Y：粘贴剪切的内容。
    • Ctrl + Q：解锁终端（当Ctrl+S锁定时使用）。

2.2 文件与目录管理​

  • 创建目录
    • mkdir /data/oldboy：创建目录。
    • mkdir -p /data/oldboy：递归创建目录，如果父目录不存在则一并创建。
  • 创建文件
    • touch /data/oldboy/oldboy.txt：创建一个空文件。
  • 查看文件/目录列表
    • ls：列出当前目录内容。
    • ls -l：显示详细信息。
    • ls -a：显示所有文件，包括隐藏文件。
  • 删除文件/目录
    • rm <文件名>：删除文件。
    • rm -r <目录名>：递归删除目录及其内容。
    • rm -rf <目录名>：强制递归删除，此命令非常危险，请谨慎使用。
  • 移动/重命名
    • mv /path/to/source /path/to/destination：移动文件或目录。
    • mv old_name new_name：重命名文件或目录。
  • 复制文件/目录
    • cp <源文件> <目标文件>：复制文件。
    • cp -r <源目录> <目标目录>：递归复制目录。
  • 查看目录结构
    • tree /data：以树状图显示目录结构。

2.3 文本编辑与处理 (Vi/Vim)​

Vi/Vim 是Linux下强大的文本编辑器，有三种主要模式：

  • 命令模式 (Command Mode)：默认模式，用于移动光标、删除、复制等操作。
  • 插入模式 (Insert Mode)：用于文本输入。
  • 底行模式 (Last Line Mode)：用于保存、退出、搜索、替换等命令。

模式转换示意图

+---------------+   i, a, o   +---------------+
|  命令模式     | ----------> |  插入模式     |
| (Command Mode)| <---------- | (Insert Mode) |
+---------------+     Esc     +---------------+
      |  :, /, ?
      |
      v
+---------------+
|  底行模式     |
| (Last Line)   |
+---------------+
      | Esc
      |
      +------------> (返回命令模式)

基本操作流程

  1. vim <文件名>：打开或新建文件，进入命令模式。
  2. 按 i, a, o 等键进入插入模式进行编辑。
  3. 按 Esc 返回命令模式。
  4. 在命令模式下输入 : 进入底行模式，执行保存退出等操作。

常用命令 (命令模式)

  • 光标移动:
    • gg：移动到文件第一行。
    • G：移动到文件最后一行。
    • ^：移动到行首。
    • $：移动到行尾。
  • 删除、复制、粘贴:
    • dd：删除当前行。
    • dG：删除光标所在行到文件末尾。
    • yy：复制当前行。
    • p：粘贴。
  • 进入插入模式:
    • o：在当前行下方新建一行并进入插入模式。

常用命令 (底行模式)

  • 保存与退出:
    • :w：保存。
    • :q：退出。
    • :wq 或 :x：保存并退出。
    • :q!：强制退出不保存。
  • 搜索与替换:
    • /<关键字>：向下搜索。
    • ?<关键字>：向上搜索。
    • :set ic 或 :set ignorecase：忽略大小写搜索。
    • :%s/旧内容/新内容/g：全局替换。
  • 显示行号:
    • :set nu

Vim异常退出恢复 如果Vim编辑时意外中断，会产生一个 .swp 交换文件。下次打开该文件时会有提示。可以使用以下命令恢复：

vim -r <文件名>

2.4 系统管理与监控​

  • 查看IP地址
    • CentOS 6: ifconfig
    • CentOS 7: ip address show 或 ip a
  • 查看主机名
    • hostname
    • uname -n
  • 查看系统信息
    • cat /etc/redhat-release 或 cat /etc/os-release
  • 查看CPU信息
    • lscpu
    • cat /proc/cpuinfo
  • 查看内存使用
    • free -h
    • cat /proc/meminfo
  • 查看系统负载
    • w
    • top
    • uptime
  • 查看磁盘空间
    • df -h
  • 关机与重启
    • shutdown -h now 或 poweroff：立即关机。
    • shutdown -r now 或 reboot：立即重启。
  • 运行级别 (Runlevel)
    • 0: 关机
    • 1: 单用户/救援模式
    • 2-4: 多用户模式 (通常2为无网络的多用户，3为标准多用户文本模式)
    • 5: 图形界面模式
    • 6: 重启

2.5 网络配置与故障排查​

  • 测试网络连通性
    • ping <IP地址或域名>
  • 测试端口开放状态
    • telnet <IP地址> <端口号>
  • SSH远程连接故障排查思路
    1. 网络层：ping <目标IP>，检查网络是否可达。
    2. 传输层：telnet <目标IP> 22，检查SSH服务端口是否开放。
    3. 应用层：ssh <用户>@<目标IP>，进行连接尝试，查看详细报错信息。
    4. 防火墙检查：检查源和目标服务器的防火墙规则是否允许22端口通信。

第三章：Linux 系统进阶管理​

3.1 用户与权限管理​

  • 创建用户
    • useradd oldboy：创建一个新用户。
    • 默认情况下，会在 /home 目录下创建同名家目录。
  • 设置密码
    • passwd oldboy：为用户设置密码（交互式）。
    • echo "123456" | passwd --stdin oldboy：免交互设置密码。
  • 切换用户
    • su - oldboy：切换到指定用户，并加载其环境变量。
  • 查看当前用户
    • whoami
    • id oldboy
  • 文件权限
    • 权限类型：读(r=4), 写(w=2), 执行(x=1)。
    • 权限归属：属主(owner), 属组(group), 其他人(others)。
    • 示例：rwx-w-r-- (724)
      • 属主：读、写、执行 (rwx)
      • 属组：写 (w)
      • 其他人：读 (r)

3.2 软件包管理​

  • RPM：
    • 特点：不能自动解决软件包之间的依赖关系。
  • YUM：
    • 特点：可以自动从配置的仓库中下载并解决软件包的依赖关系。
  • 二进制包：
    • 特点：通常是预编译好的程序，解压后即可使用，无需安装。
  • 源码包：
    • 特点：需要编译安装 (./configure, make, make install)，可以自定义功能和安装路径。

忘记包名时查找软件包

yum provides */命令名

3.3 磁盘与文件系统管理​

  • 硬链接 (Hard Link)

    • 原理：多个文件名指向同一个inode号。inode是存放文件元数据（属性）的地方。
    • 特点：
      • 不能跨文件系统创建。
      • 不能对目录创建。
      • 删除源文件，硬链接文件依然可用，直到所有指向该inode的链接都被删除，且没有进程占用该文件时，数据才会被真正删除。

  • 软链接 (Symbolic Link)

    • 原理：一个特殊的文件，其内容是另一个文件的路径。
    • 特点：
      • 可以跨文件系统创建。
      • 可以对目录创建。
      • 删除源文件，软链接会失效（悬空链接）。
    • 创建命令：ln -s <源文件> <链接文件>

  • inode与block

    • inode：存放文件的元数据，如权限、属主、大小、时间戳和数据块指针。
    • block：实际存放文件内容的数据块。
    • "No space left on device"问题：如果df -h显示磁盘空间未满，但无法写入新文件，通常是由于inode耗尽。这通常是大量小文件导致的。需要查找并删除不必要的小文件来解决。

  • 挂载 (Mount)

    • 作用：将一个设备（如硬盘分区、光驱）关联到一个已存在的目录（挂载点）上，从而访问设备中的内容。

    • 挂载光驱示例:

      mkdir /data -p
      mount /dev/cdrom /data

    • /etc/fstab 文件：系统启动时会读取此文件，自动挂载其中定义的文件系统。

3.4 系统启动与服务管理​

  • 启动脚本位置：
    • /etc/init.d/ 或 /etc/rc.d/init.d/ (SysVinit)
    • /etc/systemd/system/ (Systemd)
  • 开机自启动配置
    • /etc/rc.local：将需要开机执行的命令写入此文件，并确保其有执行权限。
      • 示例：\cp /oldboy/oldboy.txt{,.bak} && echo "backup is ok" >> /oldboy/info.log
  • 自定义开机/登录提示信息
    • 开机提示：修改 /etc/issue 文件。
    • 登录后提示：修改 /etc/motd 文件。

3.5 系统安全与优化​

  • 关闭 SELinux
    1. 临时关闭：setenforce 0
    2. 永久关闭：编辑 /etc/selinux/config 文件，将 SELINUX=enforcing 修改为 SELINUX=disabled。
  • 关闭防火墙 (CentOS 7)
    1. 停止服务：systemctl stop firewalld
    2. 禁止开机自启：systemctl disable firewalld
    3. 检查状态：systemctl status firewalld 和 systemctl is-enabled firewalld
  • 修改系统字符集
    • localectl set-locale LANG=zh_CN.utf8
    • 或临时修改：export LANG=zh_CN.utf8

第四章：MySQL 数据库入门与管理​

4.1 数据库基础概念​

  • DBMS (数据库管理系统)：用于存储和管理关键业务数据的软件。
  • 数据库类型:
    • 关系型数据库 (RDBMS): Oracle, MySQL, PostgreSQL
    • 非关系型数据库 (NoSQL): MongoDB, Elasticsearch, Redis
    • 云数据库: RDS, PolarDB, TDSQL
  • 三大MySQL厂商:
    • Oracle MySQL
    • Percona MySQL
    • MariaDB
  • 企业版本选择建议:
    • 5.6: 5.6.34+ 以上的双数版本
    • 5.7: 5.7.20+ 以上的双数版本 (目前最主流)
    • 8.0: 8.0.11+ 以上的版本

4.2 MySQL 安装与部署 (二进制包)​

安装环境准备

# 1. 创建目录
mkdir -p /data/app /data/3306/data /data/3306/binlog

# 2. 创建用户和组
useradd mysql
chown -R mysql.mysql /data

# 3. 清理系统残留
yum remove mariadb-libs -y

# 4. 安装依赖
yum install -y libaio-devel

软件安装

# 1. 解压软件包
cd /data/app
tar xf mysql-5.7.28-linux-glibc2.12-x86_64.tar.gz

# 2. 创建软链接
ln -s mysql-5.7.28-linux-glibc2.12-x86_64 mysql
chown -R mysql. /data

配置与初始化

# 1. 设置环境变量
echo 'export PATH=/data/app/mysql/bin:$PATH' >> /etc/profile
source /etc/profile

# 2. 创建配置文件 /etc/my.cnf
cat > /etc/my.cnf <<EOF
[mysqld]
user=mysql
basedir=/data/app/mysql
datadir=/data/3306/data
server_id=6
socket=/tmp/mysql.sock

[client]
socket=/tmp/mysql.sock
EOF

# 3. 初始化数据库 (5.7+)
# --initialize-insecure: 创建一个空密码的root用户
# --initialize: 创建一个带随机临时密码的root用户
mysqld --initialize-insecure --user=mysql --basedir=/data/app/mysql --datadir=/data/3306/data

注意：初始化时，datadir 必须为空目录。如果报错 data directory has files in it，需要清空该目录后重试。

启动与管理

  • 方法一：使用自带脚本 (SysVinit)

    cp /data/app/mysql/support-files/mysql.server /etc/init.d/mysqld
    service mysqld start/stop/restart

  • 方法二：使用 systemd (推荐)

    # 创建 service 文件
    vim /etc/systemd/system/mysqld.service

    [Unit]
    Description=MySQL Server
    After=network.target

    [Service]
    User=mysql
    Group=mysql
    ExecStart=/data/app/mysql/bin/mysqld --defaults-file=/etc/my.cnf
    LimitNOFILE=5000

    [Install]
    WantedBy=multi-user.target

    # 启动服务
    systemctl start mysqld.service

4.3 MySQL 基础管理​

  • 用户管理

    • 查询用户: SELECT user, host FROM mysql.user;
    • 创建用户: CREATE USER 'user'@'host' IDENTIFIED BY 'password';
    • 删除用户: DROP USER 'user'@'host';
    • 修改密码: ALTER USER 'user'@'host' IDENTIFIED BY 'new_password';

  • 授权管理

    • 授权语法 (8.0前): GRANT <权限> ON <数据库.表> TO 'user'@'host' IDENTIFIED BY 'password';
    • 授权语法 (8.0后): GRANT命令不再支持创建用户和修改密码。
    • 授权示例:
      • 授予管理员权限: GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' IDENTIFIED BY 'password' WITH GRANT OPTION;
      • 授予业务用户权限: GRANT SELECT, INSERT, UPDATE, DELETE ON wordpress.* TO 'wp_user'@'10.0.0.%';

  • 忘记root密码处理

    1. 停止MySQL服务。

    2. 使用“跳过授权表”模式启动：mysqld_safe --skip-grant-tables --skip-networking &

    3. 无密码登录MySQL：mysql

    4. 刷新权限并修改密码：

      FLUSH PRIVILEGES;
      ALTER USER 'root'@'localhost' IDENTIFIED BY 'new_password';

    5. 正常重启MySQL服务。

第五章：数据库与服务器面试精选​

5.1 Nginx 面试题​

  • HTTP工作原理 HTTP (超文本传输协议) 是Web数据交换的基础。其工作流程如下：

    1. 用户输入URL：用户在浏览器中输入网址或点击链接。
    2. DNS解析：浏览器向DNS服务器请求解析域名对应的IP地址。
    3. 建立TCP连接：浏览器与服务器通过IP地址和默认的80端口建立TCP连接（三次握手）。
    4. 发送HTTP请求：浏览器向服务器发送HTTP请求报文（如GET请求）。
    5. 服务器响应：服务器处理请求，并返回HTTP响应报文（如包含HTML内容的响应）。
    6. 浏览器渲染：浏览器接收并解析响应内容，渲染成网页展示给用户。
    7. 关闭TCP连接：数据传输完毕后，关闭TCP连接（四次挥手）。

  • 正向代理与反向代理

    • 正向代理：代理的是客户端。客户端通过代理服务器去访问外部网络，隐藏了真实的客户端信息。常用于科学上网、访问内网等场景。
    • 反向代理：代理的是服务器。客户端的请求被发送到反向代理服务器，由代理服务器将请求转发给内部网络上的真实服务器，隐藏了真实的服务器信息。常用于负载均衡、安全防护等场景。

  • 负载均衡

    • 概念：将大量的并发请求分发到多台服务器上进行处理，以提高系统的整体处理能力、可用性和扩展性。
    • 常用调度算法：
      • 轮询 (Round Robin)：按顺序将请求逐一分发给后端服务器。
      • 加权轮询 (Weighted Round Robin)：根据服务器性能分配不同的权重，性能好的服务器处理更多请求。
      • IP哈希 (IP Hash)：根据请求的源IP地址进行哈希计算，确保来自同一IP的请求始终被转发到同一台后端服务器，可以解决Session共享问题。
    • 带来的问题：如果使用轮询或加权轮询，可能会导致用户的会话（Session）信息丢失，因为用户的连续请求可能会被分发到不同的服务器上。

  • Nginx常用模块

    • ngx_http_stub_status_module：提供Nginx的状态监控信息。
    • ngx_http_autoindex_module：自动生成目录列表。
    • ngx_http_access_module：基于IP地址进行访问控制（allow, deny）。
    • ngx_http_rewrite_module：URL重写。

  • 动静分离

    • 目的：将网站的动态请求（如PHP脚本）和静态资源（如图片、CSS、JS文件）分开处理，以提高处理效率和减轻后端服务器压力。
    • 好处：
      • 静态资源由Nginx直接处理，速度快。
      • 动态请求才转发给后端应用服务器（如PHP-FPM），减少了应用服务器的负载。
      • 便于对静态资源进行缓存和CDN加速。

  • 高可用 (High Availability)

    • 概念：指系统能够长时间持续提供服务的能力，通常通过冗余和故障转移来实现。
    • 双机热备：两台服务器互为备份，一台主服务器工作，一台备用服务器处于待命状态。当主服务器故障时，备用服务器迅速接管服务。
    • Keepalived：通过VRRP协议 (虚拟路由冗余协议) 实现高可用。它通过一个虚拟IP(VIP)对外提供服务，多台服务器竞争成为Master来持有这个VIP。当Master故障时，其他Backup服务器会重新选举出新的Master来接管VIP，从而实现故障的平滑切换。

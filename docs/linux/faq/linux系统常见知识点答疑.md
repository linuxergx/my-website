## 1. Shell 环境与配置

### 环境变量与配置文件

系统和用户的环境由一系列配置文件控制，它们有特定的加载顺序，后面的配置会覆盖前面的。

- **加载顺序**:
  1. `/etc/profile` (系统级，全局)
  2. `/etc/profile.d/*.sh` (系统级，应用程序)
  3. `~/.bash_profile` (用户级，登录时加载)
  4. `~/.bashrc` (用户级，非登录交互式 Shell 加载)
  5. `/etc/bashrc` (系统级，被 `~/.bashrc` 调用)
- **`source` 命令**: 用于在当前 Shell 环境中执行脚本，使脚本中的设置（如变量、别名）立即生效。`source /etc/profile` 等同于 `. /etc/profile`。

### 命令别名 (alias)

用于给复杂的命令创建一个简单的别名。

- **定义别名**:

  ```
  alias cman='man -M /usr/local/zhman/share/man/zh_CN'
  ```

- **让别名永久生效**: 将 `alias` 定义写入用户的 `~/.bashrc` 或系统的 `/etc/bashrc` 文件中。

- **临时忽略别名**: 在命令前加反斜杠 `\`，可以临时忽略已定义的别名，执行命令本身。

  ```
  # 假设 cp 被别名为 cp -i
  \cp source.txt destination.txt # 这里的 cp 不会提示覆盖
  ```

### PATH 环境变量

`PATH` 是一个非常重要的环境变量，它定义了当执行一个命令时，系统去哪些目录中寻找这个可执行文件。

- **查看 PATH**:

  ```
  echo $PATH
  ```

- **命令查找顺序**: 当你输入一个命令时，系统会按照以下顺序查找：

  1. 别名 (Alias)
  2. 函数 (Function)
  3. 内置命令 (Built-in)
  4. 外部命令 (External, 根据 `PATH` 变量的路径顺序查找)

## 2. Shell 脚本与特性

### 引号的区别

- **双引号 `"` (弱引用)**: 会解析其中的特殊变量，如 `$`、```, `!`。变量会被替换成它的值。

  ```
  echo "$PATH" # 会输出 PATH 变量的值
  ```

- **单引号 `'` (强引用)**: 忽略所有特殊字符，将其中的所有内容都作为普通字符串处理。

  ```
  echo '$PATH' # 会原样输出字符串 "$PATH"
  ```

### 命令替换 (反引号 ```)

反引号 ``` (或 `$(...)`) 用于执行一个命令，并将其标准输出结果替换到当前命令行的位置。它不是管道符的增强版，功能完全不同。

- **示例**:

  ```
  # 将当前目录路径赋值给 a 变量
  a=`pwd`
  
  # 生成一个随机密码并赋值给 pass 变量
  pass=`uuidgen | head -c 8`
  ```

### Shell 脚本执行方式

- **顺序执行**: 脚本中的命令从上到下依次执行。
- **选择执行**: 使用 `if`, `case` 等语句进行条件判断。
- **循环执行**: 使用 `for`, `while` 等语句进行循环操作。

### for 循环语句

用于遍历一个列表，并对列表中的每个元素执行一系列命令。

- **语法**:

  ```
  for 变量 in 列表; do
      # 循环体命令
      echo "当前变量是: $变量"
  done
  ```

- **示例：批量创建用户**

  ```
  for user in wuxing{1..10}; do
      useradd $user
  done
  ```

### 特殊符号的使用

- **`[]` (方括号)**:
  - 在通配符中，表示匹配括号内任意**一个**字符。`[ab]c` 匹配 `ac` 或 `bc`。
  - 在正则表达式中，功能类似，定义一个字符集。
  - 在 Shell 中，`[ ... ]` 是 `test` 命令的另一种形式，用于条件判断。
- **`{}` (花括号)**:
  - 用于生成序列，称为“大括号扩展”。`echo {1..5}` 会输出 `1 2 3 4 5`。
  - 在 `find` 命令的 `-exec` 选项中，`{}` 作为占位符，代表 `find` 命令找到的每一个文件。
- **`()` (圆括号)**:
  - 在子 Shell 中执行命令 `(cd /tmp; pwd)`，不会影响当前 Shell 的工作目录。
  - 在正则表达式中，用于分组。`(a|b)c` 匹配 `ac` 或 `bc`。

## 3. 文件与目录管理

### 硬链接与软链接

- **文件存储三要素**:
  1. **文件名 (Filename)**: 存储在目录的 block 中，指向一个 inode 号。
  2. **inode**: 存储文件的元数据（权限、大小、所有者、时间戳）和指向数据块的指针。
  3. **数据块 (Data Block)**: 实际存储文件内容的地方。
- **硬链接 (Hard Link)**:
  - 创建一个新的文件名，指向**同一个 inode**。
  - 相当于给文件取了一个别名。删除源文件或任意一个硬链接，只要还有一个链接存在，文件内容就不会被删除。
  - 不能跨文件系统创建，不能对目录创建。
- **软链接 (Symbolic Link)**:
  - 创建一个独立的新文件，这个文件有自己的 inode。
  - 文件内容是**指向源文件的路径**。
  - 类似于 Windows 的快捷方式。如果源文件被删除，软链接就会失效。

### find 命令详解

用于在指定目录中查找文件。

- **常用选项**:
  - `-type`: 按文件类型查找 (`f` 普通文件, `d` 目录)。
  - `-name`: 按文件名查找（区分大小写）。
  - `-iname`: 按文件名查找（不区分大小写）。
  - `-size`: 按文件大小查找 (`+10M`, `-1G`)。
  - `-mtime`: 按修改时间查找（天）。
  - `-mmin`: 按修改时间查找（分钟）。
  - `-exec command {} \;`: 对找到的每个文件执行指定的命令。`{}` 是占位符，`\;` 表示命令结束。
  - `-prune`: 用于排除指定目录。

### xargs 命令详解

从标准输入读取数据，并将其作为参数传递给后续的命令。它能很好地处理由管道传递过来的大量参数。

- **与 `-exec` 的区别**:

  - `-exec`: `find` 每找到一个文件，就启动一次后续命令的进程。
  - `xargs`: 将 `find` 找到的所有文件一次性（或分批）传递给后续命令，效率更高。

- **示例**:

  ```
  # 查找所有 .txt 文件并用 cp 命令复制到 /tmp
  find /oldboy/ -type f -name "*.txt" | xargs -i cp {} /tmp
  ```

### 打包与压缩 (tar)

- **常用选项**:
  - `c`: 创建归档文件。
  - `x`: 解开归档文件。
  - `f`: 指定归档文件名。
  - `z`: 使用 gzip 进行压缩/解压缩。
  - `v`: 显示详细过程。
  - `t`: 查看归档文件内容。
  - `h`: 打包软链接指向的源文件，而不是软链接本身。

## 4. 输入输出重定向

### 标准输入、输出和错误

- **标准输入 (stdin)**: 文件描述符为 `0`，默认来自键盘。
- **标准输出 (stdout)**: 文件描述符为 `1`，默认输出到屏幕。
- **标准错误 (stderr)**: 文件描述符为 `2`，默认输出到屏幕。

### 常用重定向符号

- `<`: 输入重定向。`tr 'a' 'b' < file.txt`

- `>`: 输出重定向（覆盖）。`ls > file.txt`

- `>>`: 追加输出重定向。`ls >> file.txt`

- `2>`: 错误重定向。`command 2> error.log`

- `&>`: 将标准输出和标准错误同时重定向。`command &> all.log`

- `>/dev/null 2>&1`: 这是一个经典组合，意思是：

  1. `>/dev/null`: 将标准输出重定向到“黑洞”设备（丢弃）。
  2. `2>&1`: 将标准错误重定向到标准输出**当前的位置**（也就是 `/dev/null`）。

  - 最终效果：丢弃所有输出，让命令静默执行。

## 5. 文本处理三剑客

### grep 命令

用于在文件中查找包含指定模式的行。

- **常用选项**:
  - `-o`: 只显示匹配到的字符串。
  - `-E` (或 `egrep`): 使用扩展正则表达式。
- **正则表达式中的 `[]` 和 `|`**:
  - `[ab]c`: 匹配 `ac` 或 `bc` (字符集)。
  - `(a|b)c`: 匹配 `ac` 或 `bc` (逻辑或)。在简单场景下效果相同，但 `()` 可以用于更复杂的分组。

### sed 命令

流编辑器，用于对文本进行增、删、改、查等操作。

- **示例**:

  ```
  # 替换 IP 地址
  IP=10.0.0.10
  sed -ri "/^IPADDR=/s#(^IPADDR).*#\1=$IP#" ifcfg-eth0
  ```

### awk 命令

强大的文本分析工具，擅长按列处理文本。

- **示例**:

  ```
  # 统计网站日志的总流量（假设流量在第10列）
  awk '{sum=sum+$10} END{print sum/1024/1024/1024 " GB"}' access.log
  ```

## 6. 系统管理与权限

### 软件包管理 (yum)

- **YUM 源**: CentOS 默认的 YUM 源配置会自动选择最快的镜像站点。企业内部通常会搭建自己的私有 YUM 源以提高速度和稳定性。
- **EPEL 源**: (Extra Packages for Enterprise Linux) 是一个为 RHEL/CentOS 提供额外软件包的项目，包含了很多官方源中没有的常用软件。

### 文件权限 (Permissions)

- **八进制表示法**:
  - `r` (读) = 4
  - `w` (写) = 2
  - `x` (执行) = 1
  - `rwx` = 4+2+1 = 7
  - `rw-` = 4+2+0 = 6
  - `r-x` = 4+0+1 = 5
- **umask (反掩码)**:
  - 定义了新建文件和目录时的**默认权限**。
  - `umask` 的值是从最大权限中“减去”的权限。
  - 文件最大权限: `666`
  - 目录最大权限: `777`
  - 例如，`umask 022`，则新建文件权限为 `666 - 022 = 644`，新建目录权限为 `777 - 022 = 755`。
- **特殊权限**:
  - **SUID**: 允许用户在执行该文件时，临时拥有文件所有者的权限。
  - **SGID**: 类似 SUID，但作用于组。
  - **Sticky Bit (粘滞位)**: 通常用在 `/tmp` 这样的公共目录上，确保用户只能删除自己的文件。

### sudo 命令与配置

`sudo` 允许普通用户以其他用户（通常是 root）的身份执行命令。

- **配置文件**: `/etc/sudoers` (使用 `visudo` 命令编辑)。

- **配置语法**:

  ```
  who    where=(as_whom)    what_command
  用户   主机=(切换身份)    可执行的命令
  ```

- **示例**:

  ```
  # oldgirl 用户可以在任何主机上，无需密码执行所有命令
  oldgirl ALL=(ALL) NOPASSWD: ALL
  ```

### 防火墙与 SELinux

- **防火墙**: 在企业内网中，通常只有对外提供服务的入口服务器（如 Web 服务器、负载均衡器）需要开启防火墙。内部服务器之间为了方便管理，通常会关闭防火墙。
- **SELinux**: 一种更强的安全机制。`ls -l` 命令输出中，文件名最后的 `.` 点，就是 SELinux 上下文的标志。

## 7. 磁盘与文件系统

### inode 和 block

- **block**: 文件系统中存储**实际数据**的基本单元，通常大小为 4KB。
- **inode**: 存储文件的**元数据**（metadata），如文件大小、权限、所有者、时间戳以及指向数据 block 的指针。**文件名不存储在 inode 中**，而是存储在目录的 block 里。

### 磁盘 IO

- **IO (Input/Output)**: 指磁盘的读写操作。一次读或一次写都算一次 IO。
- **IOPS (IO per Second)**:衡量磁盘性能的重要指标，表示每秒能处理的 IO 请求数量。
- **Block 与 IO 的关系**: 读写一个大文件需要多次 IO 操作。例如，一个 100KB 的文件，如果 block 大小是 4KB，至少需要 `100 / 4 = 25` 次 IO 操作。
